# Kannagi Night Mart API

The API behind the Kannagi Night Mart website: accounts, catalog (customers see only items in stock), wishlist requests (cleared when the item is added; admins can remove them), orders, manual (in-person) sales, sales figures, a record of stock added and taken off (for the admin's Investment page: new stock bought and the value of the stock left), profit day by day and item by item (the admin's Profit page), offers (the amounts each offer card gives, set by the shop), the spin wheel (each slice's amounts and the cart it needs are set by the shop, and its text is written from them; the shop can switch the wheel off), a loyalty card (every 10th completed order earns a free item), notifications (Web Push: each new order to the shopkeepers' devices, the day's summary to admins at closing time, and customers' own news: their order confirmed, ready or cancelled, and items they asked for arriving) and the admin console. FastAPI + SQLAlchemy, Neon Postgres in production, SQLite in development. It runs on Render's own Python runtime (no Docker).

## How it's secured

```
Phone / browser ──▶ Website server ──(X-Internal-Key)──▶ this API ──▶ Neon Postgres, Cloudinary
```

- **Only the website server calls it.** The website is https://kannagimart.tech ([KannagiFrontend](https://github.com/Ganesh30112006/KannagiFrontend), on Vercel). Browsers never call the API, so it needs no CORS and no setting with the website's address.
- **Hidden without the key.** Every path except `/api/health` (which only says "ok") answers `404` unless the request carries `X-Internal-Key` equal to `INTERNAL_API_KEY`. The same value must be set where the website runs.
- **Secrets stay here.** The Neon password and the Cloudinary API secret live only in this service's environment.
- **Production refuses weak settings.** With `ENVIRONMENT=production` it won't start with missing or short secrets, without the main admin (`ADMIN_MOBILE`, `ADMIN_PASSWORD`), with a malformed Cloudinary URL, or (on Render, whose disk is wiped on every deploy) without a Postgres `DATABASE_URL`.

## Deploy on Render

`render.yaml` describes the service: region Singapore (next to the Neon database), Python 3.12 (pinned by `.python-version`), health check `/api/health`.

1. **Neon:** in your project, open **Connect** and copy the **pooled** connection string (its host contains `-pooler`).
2. **Cloudinary:** go to **Settings → API Keys** and copy the **API environment variable** (`cloudinary://<key>:<secret>@<cloud>`).
3. **Render:** choose **New → Blueprint**, connect GitHub and pick this repository. Render reads `render.yaml` and asks once for:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | the Neon **pooled** connection string |
   | `INTERNAL_API_KEY` | a random string of 32+ characters; the website server gets the same value |
   | `ADMIN_MOBILE` | the main admin's 10-digit mobile number |
   | `ADMIN_PASSWORD` | the main admin's password, 8+ characters (opens `/admin` on the website) |
   | `CLOUDINARY_URL` | `cloudinary://<key>:<secret>@<cloud>` |
   | `VAPID_PRIVATE_KEY` | optional: turns on order alerts (a notification for each new order on the shopkeepers' phones). Make one with `python -m app.webpush`; keep it the same, or every device has to turn alerts on again |

   `JWT_SECRET` is generated by Render. `ENVIRONMENT=production`, `SHOP_TIMEZONE` and `CLOUDINARY_FOLDER` come from `render.yaml`. Spaces or a newline pasted around a value are ignored.

4. **Check it:** `https://<service name>.onrender.com/api/health` answers `{"status":"ok"}`, and any other path answers `404`. If a setting is weak or missing, the deploy fails and the Render log says which one.
5. **The website:** its code already points at `https://kannagibackend.onrender.com`; on Vercel it only needs the same `INTERNAL_API_KEY` (see KannagiFrontend's README).

- **Tables:** the API creates and upgrades its tables in the Neon database by itself every time it starts. When Render starts several processes at once (`WEB_CONCURRENCY`), they take turns: one upgrades and the others find it done.
- **Free plan:** a free instance sleeps after 15 minutes without requests and takes up to a minute to wake. A paid instance type never sleeps.
- **Main admin's password:** change `ADMIN_PASSWORD` in Render's **Environment** tab and save; it redeploys, and the old password's sessions are signed out.
- **Logs:** Render dashboard → the service → **Logs**.

## CI/CD

GitHub Actions (`.github/workflows/ci.yml`) checks every push to `main` and every pull request: pyflakes, and the API built and started exactly as `render.yaml` says on a throwaway Postgres 18 (Neon's version), then asked a few questions (health says ok, other paths are hidden without the key, sign-up needs a mobile number and allows one account per number, a customer signs in with her mobile number, the main admin can sign in). CI needs no secrets and never touches Neon, Cloudinary or the live shop.

`render.yaml` sets `autoDeployTrigger: checksPass`: Render deploys a commit only after all its checks pass, and a failed check leaves the last good version running. Render's health check must pass before a new version gets any traffic. To deploy without a new commit: the service → **Manual Deploy**.

## Development

```sh
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
# create .env with JWT_SECRET, INTERNAL_API_KEY, ADMIN_MOBILE, ADMIN_PASSWORD (and ENABLE_DOCS=true for /docs)
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

With no `DATABASE_URL`, it uses `kannagi.db` (SQLite). To develop against Neon, use a separate Neon branch, never the production one, and set `CLOUDINARY_FOLDER` to a development folder so the live shop's photos are never touched.
